The shared client event contract accepts only enumerated values. The owned site's consent policy was updated to `2026-11-10`; a previous choice is requested again before the expanded match categories can be sent. The first-party analytics endpoint continues to retain event files and aggregates for 90 days.

For consented first-party account events, the browser sends the account ID to the owned analytics endpoint for bot exclusion and account-level retention. The data service replaces it with a channel-scoped HMAC before writing Redis aggregates or event archives; portal SDKs receive no account ID, platform player ID, IP address, or match identifier.

## Churn and conversion signals

- Tutorial start, individual step completion, and explicit early exit show where an engaged player stops. Closing a tab is not observable as an intentional churn event.
- Queue start, join, cancellation, wait bucket, and fixed failure category expose matchmaking friction without storing raw server errors.
- Match start, result, mode, and duration bucket distinguish conversion to play from completed play. `match_exit` counts only explicit menu exits before a result.
- Website reports include event counts and distinct sessions per UTC day, plus retention cohorts for consenting accounts. These are aggregate counts, not a reconstructed individual journey.
- Portal dashboards remain separate. We cannot claim cross-portal unique users, cross-device people, player demographics, or a single cross-platform retention rate.

## Platform policy gates

- **Poki:** external requests are blocked by default. Request approval in Settings → CSP for `https://shadowsofwar.io/api`, `wss://shadowsofwar.io/ws/`, and `wss://shadowsofwar.io/relay/<port>/ws/`; explain profile/matchmaking and externally hosted multiplayer separately. The artifact creates a persistent anonymous profile through `/api/profile/anonymous` and does not use [Poki User Accounts](https://developers.poki.com/guide/accounts). Poki's [external resources policy](https://developers.poki.com/guide/external-resources-policy) also lists external account systems as not allowed. The game has no Poki login or personal-data form, but the persistent backend profile still needs an explicit policy decision in the developer portal before claiming compliance. The live privacy page responds HTTP 200 and the Poki menu links to it. CSP approval and a clean warning panel remain unverified.
- **CrazyGames:** current artifact is 400 files and 77.39 MB, below the total 250 MB and 1,500-file limits. Since the SDK is integrated, the portal measures initial download through `Gameplay start`; the 50 MB initial cap (20 MB for mobile-home eligibility) cannot be confirmed by the local package validator. The SDK integration suppresses external sign-in and uses CrazyGames identity when present. Code audit also found that guests without a CrazyGames identity fall back to a remote anonymous profile; the SDK account-link prompt has no caller, so guest progress linking is not implemented. The [official account requirements](https://docs.crazygames.com/requirements/account-integration/) recommend guests play without an in-game account unless it can be linked, and differ between Basic and Full implementations. The private QA tool must verify the selected launch tier, guest behavior, external API/multiplayer review, initial download, and SDK lifecycle.
- **Jest:** target Basic Launch only. The official checklist requires mobile readiness, SDK health, `getPlayer()` or `getPlayerSigned()`, guest progress keyed by stable `playerId`, registration, and D1–D7 notifications for registered players. The bridge now keys/migrates progress by `playerId`, prompts only guests, marks the first playable milestone, and schedules D1–D7 (plus recommended D0). No external links or in-app advertising are included. The Simulator must still verify automated checks; mobile review covers iOS Safari and Android Chrome, under-10-second time to interactive, and 10+ minutes of stability.
